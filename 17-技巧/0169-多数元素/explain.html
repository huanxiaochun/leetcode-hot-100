169. 多数元素

简单 技巧 LeetCode ↗

像打擂台：台上站一个候选人，和他相同的数给他加一票，不同的数和他同归于尽抵消一票；票数归零就换下一个数上台。多数元素比其余所有数加起来还多，最后站在台上的一定是它。

nums（格子下面：上台 / +1 / −1）
擂台上的候选人 cand
他手里的票 cnt
同归于尽的对子（每对是两个不同的数）

  

  

  



  

    
为什么这个技巧成立

    
把每个数看成一个士兵，不同阵营的士兵一换一同归于尽。多数元素的人比其余所有人加起来还多，怎么换都消灭不完

    
1
多数元素出现 > n/2 次，其余所有数加起来 < n/2 次
2
每次抵消都拿掉两个不同的数，其中最多只有一个是多数元素
3
最坏情况：其余每个数都拿去换掉一个多数元素，多数元素仍然有剩
4
所以抵消完后擂台上留下的，一定是多数元素（其余数之间互相抵消，只会让它剩得更多）
多数 22222
其余111·
↓
一换一2222
111·
[2, 2, 1, 1, 1, 2, 2]：4 个 2 对 3 个 1，一换一之后还剩一个 2

  

  

    
归纳 · 同类题 · 易错点

    
投票法（摩尔投票）不同的数两两抵消，剩下的就是多数

    
136只出现一次的数字
同样用一个「抵消」规则代替哈希表计数：那题相同的数抵消，这题不同的数抵消，都只要 O(1) 空间
215数组中的第K个最大元素
多数元素一定是排序后的中位数 nums[n/2]，可以用快速选择 O(n) 找，但要改数组；投票法一趟扫完、不改数组
229多数元素 II（变形）
找出现次数 > n/3 的数：最多两个，所以擂台上放两个候选人，遇到第三种数就三个各抵消一票，最后还要再数一遍验证

    
先换人、再计票cnt == 0 时先让 x 上台，再算 x 和候选人是否相同（这时一定相同，cnt 变 1）。顺序反了，空擂台上的 0 会被当成候选人
不保证存在就要验证本题保证多数元素存在。如果题目不保证，投票结束后要再遍历一次，确认候选人真的出现了超过 n/2 次

  
  

    

      
时间O(n)

      

        
每个数→比较 1 次、改票数 1 次

        
一趟扫描，每个数只决定一件事：给候选人加一票，还是和他抵消一票。

      

      
2211122
cnt：1 → 2 → 1 → 0 → 1（1 上台）→ 0 → 1（2 上台）

    

    

      
空间O(1)

      

        
候选人 cand+票数 cnt

        
不用记每个数出现了几次，只记「现在谁在台上、他还剩几票」。

      

    

    

      
对比哈希 / 排序

      

        
哈希表计数，找次数 > n/2 的：O(n) 时间但 O(n) 空间。排序后多数元素一定在正中间 nums[n/2]：O(n log n)，还要改数组。题目进阶要求 O(n) 时间、O(1) 空间，投票法两样都满足。

背包问题在问什么

    
一个容量有限的背包，一堆物品，每件有「重量」和「价值」：怎么挑，才能在不超重的前提下价值最大？

    

      
A
重 1 · 值 15
B
重 3 · 值 20
C
重 4 · 值 30

      
→

      
🎒容量 4

      
⇒

      
A + B
重 1 + 3 = 4，值 15 + 20 = 35

    

    

      
为什么不能贪心
按「性价比」从高到低装，看着合理，但物品不能切开：「重 1 值 6、重 2 值 10、重 3 值 12」、容量 5，
        贪心先装 A、B 得 16，剩下 2 放不下 C；最优是 B + C = 22。局部最优拼不出全局最优。

      
为什么能 DP
只看最后一件物品：要么不放，问题变成「前 n−1 件、容量 W」；要么放，变成「前 n−1 件、容量 W − w」再加 v。
        两个子问题还是背包问题，只是更小，而且会被反复用到。所以状态要有两样东西：考虑到第几件、还剩多少容量，这就是二维表 dp[i][j]。

    

  

  

    
第一步：先写二维表

    
所有背包都从同一张表开始。行 i 是「考虑到第几件（种）」，列 j 是「容量」。每一格都只看最后这一件放不放，区别只在「放」的时候去哪一格找

    

      
1表开 (n+1) × (W+1)：多出来的第 0 行表示「一件都没有」，第 0 列表示「容量 0」，边界就不用特判

      
2一行一行往下填，每行从左往右。算第 i 行时，上一行已经全部算好

      
3答案在右下角 dp[n][W]：所有物品都考虑过、容量用满上限

    

    

      
0/1 背包：放了就不能再放

        
不放：正上方 dp[i−1][j]。放：腾出 w 的空间，第 i 件已经用掉了，剩下的容量只能装前 i−1 件，所以看上一行往左 w 格。

        
dp[i][j] = max(dp[i−1][j], dp[i−1][j−w] + v)

      
完全背包：放了还能再放

        
不放（一件都不放）：正上方。放：先放一件，第 i 种还能接着放，剩下的问题还是「前 i 种、容量 j−w」，所以看同一行往左 w 格。

        
dp[i][j] = max(dp[i−1][j], dp[i][j−w] + v)

    

    
问「有几种方法」时把 max 换成加法，第 0 行改成 dp[0][0] = 1：0/1 计数 dp[i−1][j] + dp[i−1][j−w]，完全计数（518）dp[i−1][j] + dp[i][j−w]。

  

  

    
第二步：二维表怎么压成一维

    
二维表的第 i 行只用到第 i−1 行（0/1），或者第 i−1 行加上本行左边（完全）。那就只留一行数组，每来一件物品，把它从「上一行」原地改成「这一行」

    

      
原地改到一半时，数组里同时有两行

        
「新」= 已经改成这一行，「旧」= 还是上一行。dp[j] 自己在改之前是旧的，就是正上方 dp[i−1][j]，两种方向都一样。

        
区别在左边的 dp[j−w]：正序时它已经改过，是这一行的 dp[i][j−w] → 正好是完全背包；倒序时它还没改，是上一行的 dp[i−1][j−w] → 正好是 0/1 背包。

      
例子：只有一件 A（重 1，值 15），容量 4

        
倒序：每格用到的都是上一行（全 0），A 只放一次，每格都是 15。和二维 0/1 表第 1 行一样。

        
正序：dp[2] 用到的 dp[1] 已经放过 A 了（紫色），于是 dp[2] = 30、dp[4] = 60，A 被放了 4 次。和二维完全背包表第 1 行一样。

    

    
记不住方向时，也可以先用两行数组滚动：dp[i % 2][j] 由 dp[(i − 1) % 2][…] 算出来，写法和二维完全一样，只是空间变成 2 × (W+1)。

  

  

    
计数：组合数和排列数

    
硬币 [1, 2] 凑金额 0 ~ 3 有几种方法？两种问法的状态不一样

    

      
组合数（不计顺序，518）：二维 dp[i][j]

        
硬币一种一种加进来，每种方法里的硬币都按加入顺序排好，凑 3 只有 1+1+1、1+2 两种。压成一维时还是硬币在外层、金额正序。

      
排列数（顺序不同算不同，377）：本来就是一维 dp[j]

        
最后一枚可以是任何一种，状态里没有「前 i 种」，只有金额。每个金额都把所有硬币当成最后一枚试一遍，所以金额在外层，凑 3 有 1+1+1、1+2、2+1 三种。

    

  

  

    
所有变体一张表

    
先看「每件能用几次」决定「放」时看哪一格，再看「问什么」决定初始化和合并方式。一维写法都是把二维这样压出来的

    
变体每件物品二维转移（放的时候看哪）压成一维初始化（第 0 行）例题

      
按「每件能用几次」分

      
0/1 背包最多 1 次max(dp[i−1][j], dp[i−1][j−w] + v) 上一行容量倒序全 0416、494、1049

      
完全背包无限次max(dp[i−1][j], dp[i][j−w] + v) 同一行容量正序全 0322、279、518

      
多重背包第 i 件最多 s 次把 s 拆成 1、2、4…、余数件，当成 0/1 物品倒序全 0二进制拆分

      
分组背包每组最多选 1 件max(dp[g−1][j], dp[g−1][j−w] + v)，组内每件都试容量倒序，组内物品放最内层全 0每组挑一个

      
二维费用同时有两种容量表多一维 dp[i][a][b]，看上一层两维容量都倒序全 0474 一和零

      
按「问什么」分（下面以 0/1 为例，完全背包把「放」换成同一行）

      
最大价值（不超过 W）max(不放, 放 + v)同上全 0经典背包

      
恰好装满的最大价值max(不放, 放 + v)同上dp[0][0] = 0，其余 −∞装不满的状态不能用

      
最少几件min(不放, 放 + 1)同上dp[0][0] = 0，其余 +∞322、279

      
能不能凑出不放 || 放同上dp[0][0] = true416

      
方案数（组合）不放 + 放物品在外层dp[0][0] = 1518、494

      
方案数（排列）状态只有金额：dp[j] = Σ dp[j − c]本来就是一维，金额在外层dp[0] = 1377、70

    

  

  

    
题目怎么翻译成背包

    
先找出「物品」「重量」「容量」「问什么」四样东西，再查上面那张表

    
416分割等和子集
0/1 · 能否
物品 = 每个数，重量 = 数值；容量 = sum / 2（sum 是奇数直接 false）。问能不能恰好装满。
494目标和
0/1 · 组合数
加正号的和 P、负号的和 N：P − N = target，P + N = sum，所以 P = (sum + target) / 2。问选出和为 P 的子集有几种。
1049最后一块石头的重量 II
0/1 · 最大值
把石头分成两堆，差越小越好：容量 sum / 2，价值 = 重量，尽量装满。答案 sum − 2·dp[n][sum/2]。
474一和零
二维费用
每个字符串是一件物品，有两种「重量」：0 的个数、1 的个数；两个容量 m、n。价值都是 1，问最多装几件。
322零钱兑换
完全 · 最少
硬币无限用，凑出 amount 最少几枚。第 0 行只有 dp[0][0] = 0，其余设成「凑不出」；最后还是凑不出就返回 −1。
279完全平方数
完全 · 最少
物品是 1、4、9、16… 这些平方数，容量 n，问最少几个。和 322 是同一题换了物品。
518零钱兑换 II
完全 · 组合数
硬币无限用，凑出 amount 有几种组合。就是上面动画里的 ③。
377组合总和 IV
排列数
「顺序不同算不同」：状态只有金额，金额在外层。就是上面动画里的 ④。
139单词拆分
排列（能否）
物品是单词，可以重复用；容量是字符串长度，必须按顺序拼出来，所以和 377 一样，长度在外层、单词在内层。

  

  

    
模板

    
先写二维，跑对了再压成一维。n 件物品，重量 w、价值 v，容量 W

    

      
① 0/1 背包：二维
dp = [[0] * (W + 1) for _ in range(n + 1)]
for i in range(1, n + 1):
    wi, vi = w[i - 1], v[i - 1]
    for j in range(W + 1):
        dp[i][j] = dp[i - 1][j]          # 不放
        if j >= wi:                      # 放：上一行
            dp[i][j] = max(dp[i][j], dp[i - 1][j - wi] + vi)
return dp[n][W]

      
② 完全背包：二维（只改一个下标）
for i in range(1, n + 1):
    wi, vi = w[i - 1], v[i - 1]
    for j in range(W + 1):
        dp[i][j] = dp[i - 1][j]          # 不放
        if j >= wi:                      # 放：同一行
            dp[i][j] = max(dp[i][j], dp[i][j - wi] + vi)

# ③ 组合数：max 换成 +=，第 0 行 dp[0][0] = 1
dp[i][j] = dp[i - 1][j]
if j >= c:
    dp[i][j] += dp[i][j - c]

      
⑤ ⑥ 压成一维
dp = [0] * (W + 1)
# 0/1：倒序，dp[j - w] 还是上一行
for wi, vi in zip(w, v):
    for j in range(W, wi - 1, -1):
        dp[j] = max(dp[j], dp[j - wi] + vi)

# 完全：正序，dp[j - w] 已经是这一行
for wi, vi in zip(w, v):
    for j in range(wi, W + 1):
        dp[j] = max(dp[j], dp[j - wi] + vi)

      
恰好装满、最少件数（一维写法）
from math import inf
# 恰好装满：装不满的状态设成「不可能」
dp = [0] + [-inf] * W

# 最少件数（322）
f = [0] + [inf] * amount
for c in coins:
    for j in range(c, amount + 1):
        f[j] = min(f[j], f[j - c] + 1)
return -1 if f[amount] == inf else f[amount]

      
多重背包：二进制拆分成 0/1
# 第 i 件最多 s[i] 次：拆成 1、2、4…、余数件
for wi, vi, si in zip(w, v, s):
    k = 1
    while si > 0:
        t = min(k, si)
        si -= t
        k *= 2
        ww, vv = t * wi, t * vi       # 打包成一件
        for j in range(W, ww - 1, -1):
            dp[j] = max(dp[j], dp[j - ww] + vv)

      
分组背包：每组最多选一件
for g in groups:                    # 组在最外层
    for j in range(W, -1, -1):      # 容量倒序
        for wi, vi in g:            # 组内物品在最内层
            if j >= wi:
                dp[j] = max(dp[j], dp[j - wi] + vi)
# 二维写法：dp[g][j] = max(dp[g-1][j],
#                         dp[g-1][j-wi] + vi)

    

  

  

    
复杂度

    
每一格只算一次，每格 O(1)

    
变体时间空间：二维空间：压成一维

      
0/1、完全背包O(n · W)O(n · W)O(W)

      
多重背包（二进制拆分）O(W · Σ log s)—O(W)

      
分组背包O(W · 物品总数)O(组数 · W)O(W)

      
二维费用O(n · M · N)O(n · M · N)O(M · N)

    

    
压成一维只省空间，时间不变。W 是容量的数值，不是输入的长度：W 到 10⁹ 时这个做法就不行了（这叫伪多项式时间）。

  

  

    
易错点

    
完全背包二维看错行「放」要看同一行 dp[i][j - wi]；写成 dp[i - 1][j - wi] 就变回 0/1 了。
0/1 压成一维写成正序左边的 dp[j − w] 已经被这件物品改过，等于又放了一次，悄悄变成了完全背包。
[[0] * (W+1)] * (n+1)n + 1 行是同一个 list，改一格整列都变；用列表推导建二维表。
range 的终点倒序要写 range(W, wi - 1, -1)：终点不包含，写成 wi 会漏掉 j = wi 那一格。

背包问题在问什么

    
一个容量有限的背包，一堆物品，每件有「重量」和「价值」：怎么挑，才能在不超重的前提下价值最大？

    

      
A
重 1 · 值 15
B
重 3 · 值 20
C
重 4 · 值 30

      
→

      
🎒容量 4

      
⇒

      
A + B
重 1 + 3 = 4，值 15 + 20 = 35

    

    

      
为什么不能贪心
按「性价比」从高到低装：A（15/1）、C（30/4 = 7.5）、B（20/3 ≈ 6.7）。装了 A 以后只剩 3，C 放不下，只能放 B，得 35，这次碰巧对。
        换成「重 1 值 6、重 2 值 10、重 3 值 12」、容量 5：贪心装 A、B 得 16，最优是 B + C = 22。物品不能切开，局部最优拼不出全局最优。

      
为什么能 DP
看最后一件物品：要么不放，问题变成「前 n−1 件、容量 W」；要么放，变成「前 n−1 件、容量 W − w」再加 v。
        两个子问题都是同样的「背包问题」，只是规模更小，而且会被反复用到：这正是动态规划的两个条件。

    

  

  

    
两个循环顺序，决定了题目的意思

    
同一行代码 dp[j] = max(dp[j], dp[j − w] + v)（或 dp[j] += dp[j − w]），只改循环的方向和内外层，意思就完全不同

    

      
内层容量：倒序 = 0/1，正序 = 完全

        
只有一件物品 A（重 1，值 15），容量 4，从全 0 开始：

        

        
倒序：算 dp[4] 时 dp[3] 还是旧的 0，A 只放一次，每格都是 15。

        正序：dp[2] 用到的 dp[1] 已经放过 A 了（红色），于是 dp[2] = 30、dp[4] = 60，A 被放了 4 次。

      
计数：外层物品 = 组合，外层容量 = 排列

        
硬币 [1, 2] 凑金额 0~3 的方法数：

        

        
硬币在外：先只用 1，再加入 2，凑 3 只有 1+1+1、1+2 两种，2+1 不会出现。

        金额在外：每个金额都枚举「最后一枚」，凑 3 有 1+1+1、1+2、2+1 三种。题目说「顺序不同算不同」就用这个。

题目怎么翻译成背包

    
先找出「物品」「重量」「容量」「问什么」四样东西，再查上面那张表

    
416分割等和子集
0/1 · 能否
物品 = 每个数，重量 = 数值；容量 = sum / 2（sum 是奇数直接 false）。问能不能恰好装满。
494目标和
0/1 · 组合数
加正号的和 P、负号的和 N：P − N = target，P + N = sum，所以 P = (sum + target) / 2。问选出和为 P 的子集有几种。
1049最后一块石头的重量 II
0/1 · 最大值
把石头分成两堆，差越小越好：容量 sum / 2，价值 = 重量，尽量装满。答案 sum − 2·dp[sum/2]。
474一和零
二维费用
每个字符串是一件物品，有两种「重量」：0 的个数、1 的个数；两个容量 m、n。价值都是 1，问最多装几件。
322零钱兑换
完全 · 最少
硬币无限用，凑出 amount 最少几枚。dp[0] = 0，其余设成「凑不出」；最后还是凑不出就返回 −1。
279完全平方数
完全 · 最少
物品是 1、4、9、16… 这些平方数，容量 n，问最少几个。和 322 是同一题换了物品。
518零钱兑换 II
完全 · 组合数
硬币无限用，凑出 amount 有几种组合。硬币在外层，不计顺序。
377组合总和 IV
完全 · 排列数
「顺序不同算不同」：金额在外层。注意中间值可能很大。
139单词拆分
完全 · 排列（能否）
物品是单词，可以重复用；容量是字符串长度，必须按顺序拼出来，所以长度在外层、单词在内层。

  

  

    
模板

    
一维列表的写法，n 件物品，重量 w、价值 v，容量 W

    

      
0/1 背包、完全背包
dp = [0] * (W + 1)
# 0/1：每件最多一次，容量倒序
for wi, vi in zip(w, v):
    for j in range(W, wi - 1, -1):
        dp[j] = max(dp[j], dp[j - wi] + vi)

# 完全：每件无限次，容量正序
for wi, vi in zip(w, v):
    for j in range(wi, W + 1):
        dp[j] = max(dp[j], dp[j - wi] + vi)

      
多重背包：二进制拆分
# 第 i 件最多 s[i] 次：拆成 1、2、4…、余数件
# 这几包能拼出 0 ~ s[i] 的任意件数
for wi, vi, si in zip(w, v, s):
    k = 1
    while si > 0:
        t = min(k, si)
        si -= t
        k *= 2
        ww, vv = t * wi, t * vi       # 打包成一件
        for j in range(W, ww - 1, -1):
            dp[j] = max(dp[j], dp[j - ww] + vv)

      
分组背包：每组最多选一件
for g in groups:                    # 组在最外层
    for j in range(W, -1, -1):      # 容量倒序
        for wi, vi in g:            # 组内物品在最内层
            if j >= wi:
                dp[j] = max(dp[j], dp[j - wi] + vi)
# 物品放最内层：同一个 j 只会从一件里挑一件

      
恰好装满、最少件数
from math import inf
# 恰好装满的最大价值：装不满的状态设成「不可能」
dp = [0] + [-inf] * W

# 最少件数（322）
f = [0] + [inf] * amount
for c in coins:
    for j in range(c, amount + 1):
        f[j] = min(f[j], f[j - c] + 1)
return -1 if f[amount] == inf else f[amount]

    

  

  

    
复杂度

    
状态数 × 每个状态的转移数

    
变体时间空间（一维）

      
0/1、完全背包O(n · W)O(W)

      
多重背包（二进制拆分）O(W · Σ log s)O(W)

      
分组背包O(W · 物品总数)O(W)

      
二维费用O(n · M · N)O(M · N)

    

    
W 是容量的数值，不是输入的长度：W 到 10⁹ 时这个做法就不行了（这叫伪多项式时间）。这时要换思路，比如物品很少时用折半枚举。

  

  

    
易错点

    
0/1 背包写成正序同一件会被放很多次，悄悄变成了完全背包。一维列表时，0/1 的容量一定倒序。
range 的终点倒序要写 range(W, wi - 1, -1)：终点不包含，写成 wi 会漏掉 j = wi 那一格。
组合和排列的循环顺序518（组合）物品在外层，377（排列）金额在外层。写反了数字都对不上。
恰好装满忘了 −∞用 0 初始化，算出来的是「不超过 W」的答案。恰好装满要 [0] + [-inf] * W，最后判断还是不是 −inf。

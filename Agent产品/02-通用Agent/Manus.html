上下文工程

输入输出比约 100:1，省钱靠缓存

  • KV-cache 命中率：官方说是生产 Agent 最重要的指标
  • 前缀稳定：系统提示不放精确到秒的时间戳，JSON 序列化顺序固定
  • 只追加：不修改历史动作和观察，改一个字后面缓存全失效
  • 文件当记忆：网页内容可以丢，只要留着 URL / 路径就能恢复，压缩可还原
  • 复述目标：反复重写 todo.md，对抗长上下文里的“中间遗忘”
  • 保留错误：失败的动作和报错留在上下文，模型会少犯同样的错

设计亮点

🎭

工具 mask 而非删除

动态增删工具会打破缓存，还会让历史里出现“未定义工具”。工具全留着，解码时屏蔽 logits，工具名用统一前缀（如 browser_、shell_）方便成组屏蔽。

🐍

CodeAct

动作可以是一段 Python 代码，一次组合多个操作、带循环和判断，比单个 JSON 调用更灵活。

🔀

防止照抄模式

上下文里动作太整齐，模型会机械重复。序列化时加一点结构化的变化打破惯性。

⏳

异步交付

任务可以跑很久，做完通知。用户关注结果，不用盯着对话。

常见问题

Q1为什么说 KV-cache 命中率是 Agent 最重要的指标？
参考答案
  • 输入远大于输出：每轮都带完整历史，输出只是一次工具调用
  • 缓存便宜：命中缓存的 token 价格和首字延迟都低一个量级
  • 做法：前缀稳定、只追加、序列化确定、需要时手动设缓存断点
Q2工具很多时，为什么不按需动态加载？
参考答案
  • 破坏缓存：工具定义在上下文前部，一变后面全失效
  • 引用断裂：历史里调用过的工具突然没了，模型会困惑或幻觉
  • 替代：状态机 + logits mask，只限制当前能选哪些工具
Q3上下文太长时怎么压缩，又不丢信息？
参考答案
  • 可还原压缩：丢掉网页正文，保留 URL；丢掉文件内容，保留路径
  • 文件系统：当无限大的外部记忆，模型自己读写
  • 不可逆压缩要谨慎：无法预知哪条观察在十步后有用
Q4Agent 出错了，要不要把错误从上下文里清掉？
参考答案
  • 不要：错误和堆栈是证据，模型看到后会调整策略
  • 错误恢复：是真正 Agent 能力的标志，学术评测常忽略

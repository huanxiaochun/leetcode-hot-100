人机协作与安全

能动手的 Agent，风险在“动作”

  • 接管模式：输密码、验证码时用户自己在虚拟浏览器里操作
  • 动作前确认：下单、发邮件这类有后果的操作先问用户
  • 监视模式：在邮箱等敏感网站上，用户离开页面就暂停
  • 拒绝高风险：银行转账等任务直接不做
  • 提示注入：网页里藏的指令可能劫持 Agent，用监控模型拦截
  • 随时打断：用户可以中途插话改方向，Agent 接着做

设计亮点

🖱

通用接口 = GUI

不需要每个网站做集成，屏幕就是 API。代价是慢，容易点错。

🔀

多路径选最快

能用文本就不截图，能用 API 就不点网页。可视浏览器只是兜底。

🧪

端到端 RL

在虚拟机里用强化学习训练工具使用，模型自己学会什么时候用哪个工具。

🧬

产品合并

Operator 会操作但不会深挖，Deep Research 会分析但不能动手。合并后一个任务里两样都做。

常见问题

Q1GUI Agent 和调 API 的 Agent 怎么选？
参考答案
  • API 优先：快、稳定、结果结构化
  • GUI 兜底：没有 API 的网站、老系统、需要像人一样操作的场景
  • ChatGPT Agent 的做法：两者都给，让模型按任务挑
Q2为什么要把 Operator 和 Deep Research 合并？
参考答案
  • 能力互补：真实任务常是“先查资料，再去网站操作”
  • 一个上下文：两边共享虚拟机、文件和登录状态，不用来回切
  • 统一训练：一个模型学会多种工具，比两个产品拼接更连贯
Q3能操作浏览器的 Agent，最大的安全风险是什么？
参考答案
  • 提示注入：网页内容里藏指令，诱导 Agent 泄露数据或乱操作
  • 不可逆动作：付款、发送、删除，必须人确认
  • 凭证：密码由用户在接管模式下输入，模型不经手

STEP 1
截图

→
STEP 2

→
STEP 3

→
STEP 4
本地执行
开发者代码真正点下去，再截图
↻ 标准的 tool use 循环，只是工具结果换成了截图
# 开发者实现“手”，Claude 只当“脑”
tools = [{"type": "computer_...", "display_width_px": 1024, "display_height_px": 768}]
while True:
    resp = claude(messages, tools)
    if resp.stop_reason != "tool_use": break
    act = resp.tool_use.input              # {"action":"left_click","coordinate":[x,y]}
    xdotool(act)                           # 在虚拟机里执行
    messages += [resp, screenshot()]       # 新截图作为 tool_result

截图与上下文

截图很贵，坐标要对得上

  • 分辨率：建议 1024×768 这类 XGA 尺寸，高分屏先缩放再发
  • 坐标换算：缩放后模型给的坐标，要由开发者换算回真实屏幕
  • 只留最近几张：早期截图可以丢掉，省 token
  • 每步验证：提示模型动作后截图确认结果，而不是假设成功
  • 快捷键优先：下拉框、滚动条难点，用键盘更可靠

常见问题

Q1Computer Use 的一轮循环是怎么跑的？
参考答案
  • 请求：带上 computer 工具定义和屏幕尺寸
  • 模型：返回 tool_use，如在某坐标点击
  • 开发者：执行动作，截图作为 tool_result 发回
  • 结束：模型不再调工具，返回文字
Q2纯视觉方案和读 DOM / 无障碍树的方案比，优劣在哪？
参考答案
  • 视觉优点：任何软件都能用，包括桌面程序、Canvas、远程桌面
  • 视觉缺点：截图 token 多、慢、坐标可能偏
  • DOM 优点：精确、便宜，但只限网页且结构可能很乱
  • 实践：常常混用，能拿结构化信息就别截图
Q3让模型操作电脑，怎么控制风险？
参考答案
  • 隔离：专用虚拟机 / 容器，最小权限
  • 网络：限制可访问的域名
  • 人确认：登录、付款、接受条款这类操作
  • 提示注入：截图里的文字可能是攻击，当数据处理

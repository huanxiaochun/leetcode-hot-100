按维度对比

1代码理解：索引 vs grep

🗂

先建索引

Cursor、Copilot、Devin。代码切块算向量，按语义找。

  • 好处：不知道关键词也能找到，比如「登录逻辑在哪」
  • 代价：要同步、会滞后；向量存在服务端，要过隐私审查
🔍

现查现读

Claude Code、Codex、Gemini CLI。模型自己跑 rg、读文件。

  • 好处：永远是最新代码，精确符号名找得准，不用额外服务
  • 代价：多花几轮工具调用和 token，大仓库第一次摸索慢
两派在靠拢：Cursor 的 Agent 也会 grep，建了索引的产品都保留精确搜索兜底。区别在默认先走哪条。

2执行环境：本机 vs 云沙箱 vs 云 VM

本机云端沙箱 / 容器云端整台 VM
代表Claude Code、Codex CLI、Cursor、Gemini CLICodex Cloud、Claude Code 云端会话、Copilot cloud agentDevin、Cursor Cloud Agents
能碰到什么你的文件、凭据、内网克隆下来的仓库 + 装好的依赖仓库 + 桌面 + 浏览器
环境准备现成，你装了什么它就有什么要写安装脚本 / 环境配置要配置，可存快照复用
风险命令跑在你机器上，靠审批和沙箱兜底默认限网，影响范围是一个容器同左，但能开浏览器，攻击面更大
适合边改边看、依赖本地服务的任务边界清楚、能自动测试的任务要点页面验证、端到端的任务

3同步交互 vs 异步交付

⇄

同步：人在回路里

IDE / 终端里一轮轮对话，看着 diff 逐块接受。走偏马上发现，但人要一直在场。

⏳

异步：交回一个 PR

派完就走，做完通知。能并行派很多个，但需求写不清时，跑完才发现方向错了。

  • 交互单位：同步是「一轮对话」，异步是「一个任务 / 一个 PR」
  • 补救手段：异步产品都加了中途介入，Devin 先出计划再干，Claude Code 能 --teleport 把云端会话拉回本地
  • 现状：Claude Code、Codex、Cursor 都已同时提供两种跑法，只有入口重心不同

4安全：问人 vs 关起来

手段机制谁在用
逐步审批写文件、跑命令前弹窗几家的默认档
规则白名单预先放行 npm test 这类命令Claude Code、Codex、Cursor
模型代审另一个模型判断这步该不该做Claude Code auto mode、Codex auto-review
OS 沙箱Seatbelt / Landlock / bubblewrap 限制写路径和网络Codex CLI 默认开，Claude Code 可开
换一台机器在云端容器 / VM 里随便折腾Devin、Codex Cloud、Copilot cloud agent
交付关卡只推自己的分支，开草稿 PR，CI 要人批Copilot cloud agent
弹窗越多，人越容易无脑点同意。所以趋势是沙箱兜底 + 少问，而不是问得更勤。

5项目知识：怎么告诉它「我们这里的规矩」

产品载体特点
Claude CodeCLAUDE.md、auto memory分层加载；Agent 自己也会记
CodexAGENTS.md多家工具共认的格式，越深的目录越优先
Cursor.cursor/rules按文件路径匹配才注入
DevinKnowledge、Playbooks组织级，按触发条件召回；流程模板可复用

6计费：订阅额度 vs 按用量

  • 订阅共用额度：Claude Code 和 Claude 聊天共用一个池子；Codex 用 ChatGPT 套餐的额度
  • 订阅 + 用量：Cursor、Devin 有包月配额，超出按模型价格另付
  • 纯用量：Copilot 2026-06 起改成 AI Credits，按 token 计；cloud agent 还要算 Actions 分钟
  • API key：Claude Code、Codex、Gemini CLI 都能直接用 API，按 token 付费，适合 CI
Agent 一次任务可能跑几十轮，同样的套餐价，重度用户的实际花费差几倍很常见。比价看「额度怎么扣」，别只看月费。

各产品优劣

1Claude Code

✓

优势

  • 可编程：claude -p 无头模式，能塞进脚本和 CI
  • 扩展点最全：Hooks 做确定性拦截，Skills 按需加载，子代理隔离上下文
  • 不依赖索引：代码不用上传建库，改完立刻能搜到
✗

劣势

  • 没有图形 diff 主场：看改动要靠 IDE 插件或 git
  • 只用 Claude 模型：不能在同一个会话里换别家模型
  • 大仓库摸索费 token：每次新会话都要重新 grep 一遍

2Cursor

✓

优势

  • 补全最顺手：自研 Tab 模型预测下一处改动，日常小改最快
  • 渐进式自主：Tab → Cmd+K → Agent → Cloud Agent，同一个产品里逐级放手
  • 多家模型可选：按任务挑模型，也有自研模型
✗

劣势

  • 绑定编辑器：用 JetBrains、Vim 的人要换工具
  • 索引上云：向量和混淆路径存服务端，敏感仓库要评估
  • 花费难预估：前沿模型按用量扣，重度 Agent 使用成本上升快

3OpenAI Codex

✓

优势

  • 沙箱默认开：OS 级限制写路径和网络，放手跑也出不了边界
  • CLI 开源：能看源码、自己改
  • 套餐里自带：有 ChatGPT 订阅就能用，云端任务可并行
✗

劣势

  • 云端要配环境：安装脚本写不好，Agent 就跑不了测试
  • 云端默认断网：要装包、调外部服务得逐个放开域名
  • 只用 OpenAI 模型：登录 ChatGPT 账号时没法换别家

4Devin

✓

优势

  • 像派活给同事：Slack、Jira 里 @ 一下就开工，交回 PR
  • 整台开发机：有浏览器，能点页面验证前端
  • 组织级记忆：Knowledge、Playbooks 让经验在团队里复用
✗

劣势

  • 反馈慢：VM 启动 + 异步执行，小改动不如本机快
  • 需求要写清楚：模糊任务跑完才发现偏了，浪费额度
  • 代码和环境上云：要接入仓库、配 VM，私有部署走企业版

5参照产品

🐙

GitHub Copilot

  • 优：issue 指给它就开工，草稿 PR + 防火墙 + CI 审批，治理最贴近 GitHub
  • 劣：cloud agent 每次在 Actions 里冷启动；按 token 计费后成本难估
🏄

Devin Desktop（原 Windsurf）

  • 优：本机 IDE + 云端 Devin 同一个账号，本地和异步能接力
  • 劣：一年内两次易主又改名，原 Cascade 已下线，插件和习惯要迁移
♊

Gemini CLI

  • 优：Apache 2.0 开源，长上下文能一次读进很多文件
  • 劣：2026-06 起免费额度和个人订阅停服，Google 主推 Antigravity CLI，只剩企业授权和付费 API key

常见问题

Q1Cursor 建索引、Claude Code 不建，谁对？
参考答案
  • 索引赢在：模糊问题、超大仓库、补全要毫秒级拿上下文
  • grep 赢在：精确符号、永远最新、代码不出本机
  • 实际：都是混合检索，只是默认路径不同；模型越强，grep 多几轮的代价越小
Q2异步 Agent 为什么交付的是 PR，而不是直接改主干？
参考答案
  • 可审查：diff + 测试日志，人看完再合
  • 可回滚：分支隔离，坏了直接关 PR
  • 复用现有流程：CI、代码评审、分支保护都不用新造
Q3本机 Agent 和云端 Agent，安全上各怕什么？
参考答案
  • 本机：命令碰到你的凭据和内网，靠审批 + OS 沙箱 + deny 规则
  • 云端：仓库里藏的提示注入诱导它把代码外传，靠默认断网 + 域名白名单
  • 共同：给的权限越小越好，密钥别放进 Agent 能读到的地方
Q4为什么几家都在补「另一半」？
参考答案
  • 任务大小不一样：小改动要同步快，大任务要异步并行
  • 能接力：Claude Code 的 --teleport、Devin Desktop + Devin Cloud，本地和云端互相移交
  • 结果：差异从「有没有」变成「默认入口在哪、额度怎么扣」

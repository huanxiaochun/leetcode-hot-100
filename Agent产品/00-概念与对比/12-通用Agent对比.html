👀

同步

Claude in Chrome、桌面 Computer Use：在你眼前操作。能随时叫停，但它用你的电脑时你最好别抢鼠标。

4安全：能动手的 Agent，风险在动作

风险典型做法
提示注入网页、邮件里藏指令；ChatGPT 用监控模型拦，Claude in Chrome 每步过分类器
不可逆动作付款、发送、删除前停下问人；部分高风险任务直接拒绝
凭据云端靠用户接管输入密码；本机方案直接复用登录态，所以权限范围更大
敏感网站ChatGPT 的监视模式：用户离开页面就暂停
企业管控管理员限制可访问域名、可用连接器、网络出口
分类器和监控模型降低注入成功率，不能归零。涉及钱和对外发送的步骤，保留人工确认。

各产品优劣

1Manus

✓

优势

  • 工具最全的云电脑：浏览器、Shell、Python、部署网页都在一个沙箱里
  • 过程可回放：每一步屏幕都能看、能分享
  • 两种浏览器：云端隔离浏览器 + 本地 Browser Operator 用你的登录态
✗

劣势

  • 积分难预估：复杂任务一次能扣掉很多积分，跑偏了也照扣
  • 不自研基座模型：能力上限跟着第三方模型走
  • 归属变动：Meta 收购被叫停后要拆分，部分用户被要求备份数据

2ChatGPT Agent（现为 ChatGPT Work）

✓

优势

  • 多路径选最快：连接器、文本浏览器、终端、可视浏览器按任务挑
  • 云端 + 桌面：Work 在网页跑云端，桌面 app 还能用你的电脑
  • 入口最大：就在 ChatGPT 里，不用装别的
✗

劣势

  • 产品变得快：Operator → Agent → Work，Atlas 浏览器一年内就下线，教程很快过时
  • 截图路径慢：遇到只能点的网站，速度和准确率明显下降
  • 用量按任务大小扣：长任务吃额度，复杂度难事先估

3Claude Computer Use（API）

✓

优势

  • 整个桌面都能操作：不限浏览器，老系统、桌面软件也行
  • 环境完全自控：数据不出自己的机器，能嵌进自己的产品
  • 和 bash、编辑工具一起给：能用命令就不点界面
✗

劣势

  • 要自己搭：虚拟桌面、截图、坐标换算、执行器都是开发者的活
  • 贵且慢：每步一张截图，token 多、延迟高
  • 安全自负：隔离、权限、确认都得自己做

4Claude in Chrome / Cowork

✓

优势

  • 用现成登录态：内部后台、供应商门户这类没连接器的系统也能操作
  • 少弹窗：分类器判安全就自动执行，不用每步批
  • 跨设备接力：Chrome、桌面、网页、手机同一个会话
✗

劣势

  • 爆炸半径大：它拿的是你的真实账号，被注入时后果更直接
  • 占用你的电脑：本机操作时不适合同时干别的
  • Chrome 绑定：浏览器能力主要在 Chrome 和 Claude 桌面 app 里

5参照产品

✨

Genspark

  • 优：一个指令自动分派给不同模型和工具，出 PPT、表格这类成品快
  • 劣：偏内容生成，碰需要登录的业务系统时不如本机浏览器类
🗄

Operator（已退场）

  • 优：第一个面向大众的「只看截图」浏览器 Agent，证明了路线可行
  • 劣：只有可视浏览器，慢；后来并入 ChatGPT Agent

常见问题

Q1云端 VM 和本机浏览器两条路，为什么各家都在同时做？
参考答案
  • 云端：安全、能后台跑，但没有登录态，常被网站当机器人
  • 本机：登录态现成，但风险落在真实账号上
  • 结论：任务不同，选路不同；Manus 加 Browser Operator、ChatGPT 加桌面版都是补另一半
Q2纯视觉操作这么慢，为什么还要做？
参考答案
  • 覆盖面：没有 API 的老系统、桌面软件、Canvas 页面只能靠它
  • 不用逐家集成：屏幕是通用接口
  • 用法：放在最后一档兜底，前面先试连接器和代码
Q3用分类器代替逐步审批，安全吗？
参考答案
  • 为什么要换：每步都问，人会麻木地点同意
  • 分类器做什么：判断这一步是否安全、是否符合用户原始请求
  • 边界：降低注入成功率但不归零；付款、发送仍要人确认，企业再加域名白名单
Q4ChatGPT Agent 为什么被 Work 取代？
参考答案
  • 任务变长：Work 定位能跑几个小时、交付表格和 PPT 的成品
  • 底座统一：Work 内置 Codex 的能力，和 Codex 共用额度和管控
  • 补桌面：桌面 app 能用你的电脑，不再只靠云端浏览器

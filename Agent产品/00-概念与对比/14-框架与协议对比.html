# 同一个工具，两家 function calling 格式不同
# OpenAI Responses API
{"type": "function", "name": "get_weather", "parameters": {...}}
# Anthropic Messages API
{"name": "get_weather", "input_schema": {...}}
# MCP Server 写一次，Host 负责转成各家格式喂给模型
  • 三者是叠加关系：MCP 的工具最后还是变成 function calling 给模型；A2A 的远程 Agent 在调用方眼里常被包装成一个工具
  • 框架支持：表里的框架都能接 MCP；Google ADK 和 MAF 原生支持 A2A
  • MCP 新版：去掉了 initialize 握手和 Mcp-Session-Id，远程 Server 能放在普通负载均衡后面水平扩展

各产品优劣

1LangGraph

✓

优势

  • 流程显式：图是代码，可测、可审、可预期
  • checkpoint 一套多用：恢复、审批、时间旅行都建在它上面
  • 不藏东西：不绑模型，不替你写 prompt
✗

劣势

  • 概念多：State、reducer、super-step，样板代码多
  • 恢复有坑：中断的节点从头重跑，副作用要幂等
  • 好用的配套收费：trace、评测、托管都在 LangSmith

2OpenAI Agents SDK

✓

优势

  • 原语少：Agent、Handoff、Guardrail，半天上手
  • trace 开箱即用：不写代码就能看全链路
  • 补上长任务：2026-04 起有沙箱执行和长任务 harness
✗

劣势

  • 流转靠模型：Handoff 选错 Agent 时只能调提示词
  • 数据出境：trace 默认传 OpenAI，合规场景要关掉或换后端
  • 托管工具绑模型：网页搜索、文件检索等只在 OpenAI 模型上能用

3Claude Agent SDK（参照）

✓

优势

  • 开箱就是能干活的 Agent：文件、Bash、搜索、权限、Hook、子代理都现成
  • 上下文管理成熟：压缩、缓存是 Claude Code 打磨过的
  • 复用扩展：MCP、Skills 直接用
✗

劣势

  • 只能用 Claude：模型换不了
  • 运行重：底层拉起 Claude Code 进程，要带文件系统的容器
  • 没有图编排：固定流程要自己在外层写代码控

4Coze / 火山方舟

✓

优势

  • 非开发也能搭：拖节点、配插件、挂知识库
  • 多渠道发布：飞书、抖音、API、网页 SDK
  • 方舟便宜：模型价格低，有上下文缓存和批量推理
✗

劣势

  • 复杂逻辑难维护：画布上没有像样的版本管理和测试
  • 迁移成本：状态和知识库在平台里，搬走要重做
  • 生态偏国内：豆包为主，海外渠道少

5CrewAI（参照）

✓

优势

  • 直观：写角色、目标、背景就是一个 Agent
  • Flow 兜底：事件驱动的确定流程，里面再套 Crew
✗

劣势

  • 提示词藏在框架里：效果不好时要翻源码调
  • 自主协作难控：经理模式下轮数和 token 不好预估

6Microsoft Agent Framework（参照）

✓

优势

  • 两家合一：AutoGen 的多 Agent + Semantic Kernel 的企业特性
  • Python 和 .NET：微软栈团队首选
  • OTel、A2A、MCP 都内置
✗

劣势

  • 迁移：AutoGen、SK 的老代码要改写
  • 偏 Azure：托管、身份、监控最顺的路径都在 Azure

7Google ADK（参照）

✓

优势

  • 语言多：Python、TypeScript、Go、Java、Kotlin
  • 确定和自主混用：顺序 / 并行 / 循环 Agent 套 LLM Agent
  • A2A 原生：调远程 Agent 像调子 Agent
✗

劣势

  • 偏 Gemini + Google Cloud：内置工具和托管都在这条线上
  • 多语言不齐：各语言版本独立实现，特性进度不一致

8Dify（参照）

✓

优势

  • 开源自部署：数据留在内网
  • RAG 和工作流成熟：模型不绑，插件接各家
✗

劣势

  • 许可证有附加条件：做多租户 SaaS 要商业授权，前端 Logo 不能去
  • 画布天花板：和 Coze 一样，复杂逻辑难测难改

常见问题

Q1LangGraph 和 OpenAI Agents SDK 本质区别是什么？
参考答案
  • 谁定流程：LangGraph 开发者画边；Agents SDK 模型通过 Handoff 决定
  • 状态：LangGraph 每步 checkpoint；Agents SDK 主要存对话
  • 代价：LangGraph 更可控但代码多；Agents SDK 上手快但复杂流程难管
  • 能组合：LangGraph 节点里也可以跑一个 SDK 的 Agent
Q2Function calling、MCP、A2A 是什么关系？
参考答案
  • Function calling：模型怎么表达「我要调工具」，各家格式不同
  • MCP：工具怎么被发现和执行，一次实现到处用
  • A2A：把任务委托给一个看不到内部的 Agent，有任务状态
  • 叠加：MCP 工具最后转成 function calling；A2A 的远程 Agent 常被包成一个工具
Q3低代码平台做到什么程度该迁到代码框架？
参考答案
  • 信号：画布节点多到看不清、改一处坏一处、没法回归测试
  • 信号：要细粒度权限、复杂状态、和内部系统深度集成
  • 怎么迁：先把稳定的子流程写成代码服务，平台调它，逐步替换
  • 别过早迁：需求还在变时，低代码迭代更快
Q4AutoGen 现在还该用吗？
参考答案
  • 新项目不用：AutoGen 和 Semantic Kernel 已进入维护模式，只修 bug 和安全问题
  • 继任者：Microsoft Agent Framework，2026-04 发布 1.0
  • 老项目：按官方迁移指南逐步改，不急着一次重写
Q5Claude Agent SDK 和直接调 API 自己写循环有什么区别？
参考答案
  • 自己写：只拿到模型，工具、权限、压缩、重试全要自己造
  • SDK：拿到 Claude Code 的整套循环和内置工具，几行代码就能读写文件、跑命令
  • 代价：要跑在带文件系统的容器里，只能用 Claude
  • 选法：Agent 要操作文件和命令行用 SDK；只是对话加几个 API 工具，自己写循环更轻

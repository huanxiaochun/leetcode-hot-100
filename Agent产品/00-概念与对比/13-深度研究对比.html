按维度对比

1检索方式

方式谁在用好处代价
自建索引Perplexity；Gemini 直接用 Google 的索引快，能控排序和来源质量爬虫和索引要长期投入，有版权和反爬争议
搜索 APIOpenAI、Claude 的搜索工具不用养索引，接上就能用结果质量受上游限制，按次付费
浏览器读全文四家都会打开网页读；ChatGPT Agent、Comet 能操作网页拿到摘要之外的细节、PDF、表格慢，每页都占上下文
检索决定上限：搜不到的东西，模型再强也写不出来。

2研究流程

1
澄清问题
长任务跑偏代价大，先对齐范围
OpenAI：先反问几个问题
Gemini：直接给计划让你改
Perplexity / Claude：多数直接开跑
2
规划
拆子问题，定先查什么
Gemini：计划公开、可编辑
Claude：主 Agent 写计划，存进记忆
OpenAI：藏在模型推理里
3
多轮搜索阅读
读到新线索就改方向再搜
OpenAI：一条循环串着搜读，可跑 Python
Claude：同时派 3~5 个子 Agent
Perplexity：自家搜索 + 沙箱
4
写报告
汇总成文，把论点和来源对上
Claude：单独的引用 Agent 补引用
其余：边写边插引用
↻
中途干预
OpenAI 2026-02 起可随时打断，改方向或改可用来源

3耗时

产品典型耗时运行方式
OpenAI5~30 分钟后台跑，侧栏看进度，完成后通知
Perplexity快答秒级，Research 几分钟同一个输入框切模式
Gemini几分钟起确认计划后后台跑
Claude几分钟到几十分钟子 Agent 并行，宽题目省时间
时间长是因为读得多。问题简单时用研究模式，是在浪费额度。

4引用方式和可信度

产品引用怎么给能核查到哪
OpenAI段落内链接侧栏有活动记录和访问过的网页
Perplexity每句后标 [1][2]，来源卡片放答案上方粒度最细，点编号直达原文
Gemini正文标注 + 文末来源列表能看计划和浏览过的网站
Claude内联引用成文后由引用 Agent 逐条对齐来源
  • 来源质量：官方、论文 > 新闻 > 论坛、营销页
  • 引用是否真支撑这句话：链接真，内容对不上，是最常见的错
  • 是否说明不确定：证据冲突时有没有明说

🔢

报告 + 来源列表，引用密度最高。

🧾

6幻觉与引用错误的风险

错误类型表现缓解机制
编造来源给出不存在的链接引用编号只能来自检索结果（Perplexity 的做法）
引用错配链接真，但不支撑这句话成文后单独校验（Claude 的引用 Agent）
来源不可靠引用论坛、营销页、转载限定可信站点（OpenAI 2026-02 起支持）
过度自信证据不足也下定论提示要求标出不确定；人工抽查关键结论
误读原文数字、时间、主语搞错关键事实多源交叉验证
OpenAI 发布时自己写明：Deep Research 会幻觉、难以区分权威信息和传言、置信度校准不好。四家都一样，引用是让人能核查，不是保证正确。

7成本

产品用户侧开发者侧
OpenAI含在 ChatGPT 套餐里，按月有次数额度，档位越高越多专用的 o3 / o4-mini-deep-research 已于 2026-07-23 下线，改用通用模型 + 搜索工具自己搭
Perplexity免费版次数有限，付费档更多有 API，型号和价格变动频繁，以官网为准
Gemini免费版有限，付费档更多Interactions API 里的 Deep Research Agent（预览）
Claude付费套餐才有没有单独的 Research API，用搜索工具 + Agent SDK 自己搭
Anthropic 公开的数据：它的多 Agent 研究系统，token 用量约是普通聊天的 15 倍。研究模式贵，主要贵在读得多。

各产品优劣

1OpenAI Deep Research

✓

优势

  • 策略是练出来的：端到端 RL，读到新线索会自己改方向
  • 先反问：开跑前对齐范围，少跑偏
  • 能算：跑 Python 处理表格、画图
  • 可控性补上了：限定站点、接 App / MCP、中途打断
✗

劣势

  • 慢：动辄十几分钟，简单问题不划算
  • 额度紧：每月次数有限，低档套餐不够用
  • 来源判断弱：官方承认会引用不权威来源
  • API 断档：专用模型已下线，开发者要自己搭

2Perplexity

✓

优势

  • 检索自己掌握：爬虫、索引、排序都是自家的
  • 引用最细：句级编号，核查成本最低
  • 模型可换：2026-02 起 Research 跑在 Claude Opus 4.6 上
  • 快慢一体：快答和研究在同一个产品里切换
✗

劣势

  • 默认浅：快答只检索一两轮，复杂题要手动切 Research
  • 标了也会错：模型可能误读原文，编号只保证来源存在
  • 来源争议：被出版方起诉、被指绕过反爬，部分站点会屏蔽
  • 推理靠别人：深度研究的质量取决于第三方模型

3Gemini Deep Research（参照）

✓

优势

  • 检索底子厚：直接用 Google 搜索，覆盖广、更新快
  • 计划可改：跑之前就能删改子问题
  • 生态打通：读 Gmail / Drive，导出到 Docs
✗

劣势

  • 多一步交互：要先看完、确认计划
  • API 在预览：只能走 Interactions API
  • 绑 Google 生态：私有数据最好也在 Google 里

4Claude Research（参照）

✓

优势

  • 并行：子 Agent 各开一个上下文，宽题目更快
  • 引用单独校验：成文后再派引用 Agent 对来源
  • 私有数据：接 Google Workspace 和连接器
✗

劣势

  • 贵：多 Agent 约 15 倍 token
  • 协调难：官方提到早期会派过多子 Agent、重复搜同一件事
  • 没有 API：只能在 Claude 应用里用

常见问题

Q1Perplexity 为什么自建索引，别家多用搜索 API？
参考答案
  • 定位不同：Perplexity 的核心产品就是搜索，检索质量是它的护城河
  • 可控：自己控排序、来源权重、段落切分，延迟也更低
  • 代价：爬虫和索引要长期投入，还要面对版权和反爬
  • 别家：模型厂商的强项在推理，搜索交给上游更划算
Q2单 Agent 循环和多 Agent 并行，研究效果差在哪？
参考答案
  • 单循环：上下文连贯，适合一条线索追到底；宽题目要串行跑很久
  • 并行：每个子 Agent 独立上下文，适合拆得开的宽题目
  • 并行的代价：token 多很多，子 Agent 之间会重复搜、结论难合并
  • 判断：子问题之间依赖少，才值得拆
Q3每句都标了引用，为什么还会错？
参考答案
  • 错配：链接是真的，但原文说的不是这句话
  • 误读：数字、时间、主语被模型改了
  • 来源差：引用本身就是转载、营销页、过时内容
  • 防：成文后逐句校验、限定可信站点、关键事实多源
Q4先出计划（Gemini）和先反问（OpenAI）有什么区别？
参考答案
  • 共同目的：长任务开跑前对齐范围，成本最低
  • 反问：用户只回答几个问题，负担轻，但看不到后面怎么查
  • 计划：用户直接看到子问题清单，能删改，但要花时间读
  • 自己做时：范围模糊用反问，用户是专家用可编辑计划

1Agent 层面的几条规矩

  • 局部改优先：MG 有「从头生成」和「局部改」两个工具。改字、改颜色、换图走局部改，更便宜，也不动用户满意的部分
  • 花钱先问：一轮要重做 3 个以上动画，或要重做用户没点名的，先问用户
  • 每次生成都留版本：想换回旧版不扣费
  • 配音变了要提醒：改口播或换音色后动画节奏对不上，标出哪些动画需要重做，由用户决定

常见于知识科普、产品讲解、数据可视化。花生的 MG 产物是 HTML 动画，最后录成视频。

「Opus 5.5 也能做视频」，花生的优势在哪

先承认：通用大模型确实能写出一段不错的动画代码

Opus 5.5 这类模型能写 HTML 动画、能写剪辑脚本。但「写出一段动画」和「交付一条能发的视频」之间，差的是一整条生产线。

环节只用通用大模型花生
配音没有，要自己接 TTS多种音色、声音克隆，按配音排时间轴
素材没有素材库，也没有版权素材按分镜内容检索视频素材，能混排用户自己的素材
BGM没有按风格推荐，能按用户反馈重选
渲染导出自己搭渲染环境逐镜 GPU 渲染，直接导出成片
质量下限每次即兴发挥，好坏不稳模板库 + 14 套风格兜底
修改说一句改动，往往整段重写结构化工程，只改受影响的分镜
成本每一步都调大模型确定性步骤交给工程，主 Agent 用便宜的 flash 类模型

改版一：沙箱化

一句话：每个用户项目一台独立的云端「电脑」，Agent 在里面读写项目文件、调用工具

沙箱里跑的是一个现成的 Coding Agent 内核，花生只提供视频业务的工具、技能和子 Agent。

1先说好处

🧱

用户之间互不影响

一个项目一台独立的机器，一个项目出问题，不会拖垮别人。

💬

对话不会丢

机器回收前把会话和项目文件存下来。用户隔几天回来，Agent 还记得聊过什么。

⚙

不用自己维护 Agent 内核

上下文压缩、权限、技能、子 Agent、会话恢复都是现成的，团队只做视频业务。

⚡

打开就能用

新建沙箱约 0.5 秒，去掉了「正在唤醒」的等待。

出站网络还没收紧。方向是白名单：只放行干活必需的服务，其余内网一律拒。

改版二：技能市场

一句话：一个「技能」就是一个标准的 Claude Code 插件，代表一种做视频的玩法

作者把它打包上传到技能社区；用户在花生 Pro 里选一个技能建项目，平台在这个项目的沙箱里运行它。内部叫 Flow 插件平台，目前在预发阶段，只在花生 Pro 开放。

1先说好处

🎬

对用户：玩法变多

选一个技能就能做一类视频，不再局限于口播加信息图。

✍

对作者：门槛低

用熟悉的 Claude Code 插件格式写，本地和线上效果一致，一条命令发布。

🏗

对平台：越用越值钱

新玩法不占核心团队排期；配音、素材、渲染、编辑器被每个技能反复复用。

🚀

对模型升级：自动受益

插件按标准写，换上更强的模型，技能效果跟着变好，平台不用改。

2解决什么问题

以前技能市场之后
每加一种剪辑流程，平台、前端、后端都要改写一个插件就行，平台和前端不用动
只擅长口播 + 信息图，内容形态窄内部团队和外部作者都能按需加玩法，比如需要歌词对齐、镜头编排的视频
花生的能力只能在花生里用插件按 Claude 标准写，在 Claude Code、Codex 里能用的写法，平台上不改就能跑
第三方代码不敢跑插件代码一律进隔离外壳，拿不到平台凭据，也看不到别的项目

3一个技能里有什么

插件内容平台怎么用
skills / agents / commands交给 Claude Code 原生加载，语义不变
.mcp.json 里的 server插件的代码。由平台拉起、放进隔离外壳；平台是它们唯一的调用方
项目数据 server（最多一个）对外提供标准格式的「项目快照」，前端编辑器、播放器、导出都读它
hooks只支持命令和 MCP 工具两种，平台在外壳里执行

5关键设计

🧱

插件代码必须独立进程 + OS 隔离

实测同进程的隔离手段（Worker、vm 等）都能逃逸。插件进外壳：只读系统目录，只能写工作区，清空环境变量，丢掉全部权限。

🎯

平台是唯一的调用方

模型、编辑器、hooks 调插件都经过平台，权限、计费、trace 只在一处做。

🔌

平台能力走官方网关

配音、素材、录制统一调官方工具，插件不自己拼请求、不碰凭据，计费和身份由网关注入。

📐

项目快照是标准数据

不管插件内部怎么存，对外都交同一种格式。前端编辑器和导出不用为每个技能单独适配。

局限与下一步

▭

内容形态窄

擅长口播加信息图，剧情、Vlog 这类画面叙事做不好。技能市场是主要的解法。

▦

效果上限受模板约束

高要求用户觉得像模板。方向是 Pro 版用更强的模型，允许在模板基础上改写动画。

⏳

长视频慢

链路长，MG 生成和渲染要排队。方向是多分镜并行、渲染优先队列。

↔

精细修改难

「往左挪一点」这类描述理解不稳。方向是在画布上点选元素再用自然语言改。

怎么衡量改进：成片率、阻断错误率、平均耗时、单片成本、用户修改轮数。

常见问题

Q1Opus 5.5 也能做视频，为什么还要花生？
参考答案
  • 差一条生产线：模型能写动画代码，但配音、素材、BGM、音画对齐、渲染导出都没有
  • 质量下限稳：模板和风格兜底，不靠模型每次即兴发挥
  • 可编辑、成本低：结构化工程只改受影响的分镜；确定性步骤交给工程，主 Agent 用便宜模型
  • 模型变强是利好：沙箱和技能市场让任何强模型都能接进来，模型负责想，平台负责做
Q2为什么要做沙箱？直接在服务里跑 Agent 不行吗？
参考答案
  • Agent 需要文件系统：项目文件、技能文档、会话记录都要有地方放，按需读
  • 隔离：一个项目一个实例，用户之间互不影响
  • 复用成熟内核：压缩、权限、技能、子 Agent、会话恢复都是现成的，不用自己维护 loop
  • 代价：冷启动和实例成本，用 MicroVM 内存快照和空闲回收压下来
Q3换 Claude Code 内核，为什么主模型还用 flash 类模型？
参考答案
  • 内核和模型是两回事：换的是 harness（循环、压缩、权限、技能机制），模型可以不变
  • 成本不变：内部模型网关支持 Anthropic 协议，flash 类模型照样能用
  • 按需升级：Pro 版或关键步骤再换更强的模型
Q4技能市场让第三方代码跑在你的平台上，怎么保证安全？
参考答案
  • 独立进程 + OS 隔离：插件代码进外壳，只能写工作区，清空环境变量，丢掉全部权限
  • 拿不到凭据：要用平台能力就调官方网关，身份和计费由网关注入
  • 平台是唯一调用方：所有调用都过平台，能统一做权限、日志和 trace
  • 还要补的：出站网络白名单
Q5为什么技能要用 Claude Code 插件格式，不自定义一套？
参考答案
  • 作者零学习成本：skills、agents、hooks、MCP server 都是现成概念
  • 可移植：在 Claude Code、Codex 里能用的写法，平台上不改就能跑
  • 扩展字段可选：花生专属的设置放在扩展字段里，别的工具不认识也不影响运行

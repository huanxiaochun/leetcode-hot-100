LibTV

产品定位

LiblibAI 做的 AI 视频创作平台：一块无限画布串起剧本、分镜、出图、出视频，人和 AI Agent 用的是同一条生产线
公司
演语科技 Evoken（LiblibAI 母公司）
上线
2026 年初
形态
网页画布、桌面客户端、Chrome 扩展、OpenAPI / MCP
主要用户
短剧和漫剧团队、影视、广告、品牌
一句话记住：LibTV 卖的不是「某个视频模型」，而是交付成片的整条工作流。模型都是外部的，它负责把模型编排进剧本 → 分镜 → 成片的流程里。

核心：无限画布

不用时间轴，用节点图

每个节点是一种产物，节点之间连线表示「拿上一步的结果做下一步」。整条流程可以存成模板复用。

T

文本 / 剧本

故事、剧本、分镜脚本。

▣

图片

角色三视图、场景、分镜画面。

▶

视频

图生视频、文生视频，每个镜头一个节点。

♪

音频

配音、配乐。

1一条典型的成片流程

1
写剧本
自己写，或让 Agent 根据一句话扩写
2
剧本 → 分镜
拆成分镜脚本，批量出分镜图；支持 9 宫格、25 宫格拆分
3
定角色和场景
三视图、360° 展示，后面每个镜头都参考它，保持人设不崩
4
逐镜生成视频
每个镜头单独选模型、调灯光和运镜
不满意 → 只重做这一个节点
✓
配音配乐，拼成片
据第三方评测，最后的完整剪辑还要靠外部工具

给 AI Agent 用

LibTV 的卖点：人和 Agent 是「平等的用户」

人在画布上点，Agent 通过接口调用，走的是同一条生成管线，产物落在同一块画布上。Agent 做完，人可以打开画布接着改。

接入方式怎么用适合谁
libtv-skills开源技能包，npx skills add libtv-labs/libtv-skills 装进项目，配一个 Access KeyOpenClaw 等支持 Skills 规范的 Agent
Remote MCP官方 Codex 插件目录，装上后走 OAuth 登录，每人用自己的账号授权Codex 等支持远程 MCP 的客户端
Chrome 扩展 + 桌面端侧边栏连上画布用 Agent 对话；右键把网页上的图片、视频、音频收进素材库人自己用

优势与不足

✓

工作流完整

剧本、分镜、角色、镜头、配音在一块画布上，不用在多个工具之间来回倒。

✓

每一步都能单独改

节点之间相互独立，改一个镜头不影响别的。

✓

模型一站式

Seedance、可灵等视频模型，加上语言、图片、音频模型，一个账号都能用。

✓

Agent 友好

开源 Skills、远程 MCP，外部 Agent 能直接调。

!

Agent 控制粒度粗

据第三方评测，接口没法精细操作单个画布节点，也不能重命名、删除项目。

!

成片剪辑弱

内置编辑做不完最终剪辑，要导出到别的工具。

!

被质疑是「Token 中转站」

不做底座模型，能力主要来自聚合主流模型。原厂降价或别家更好用，用户可能就走了。

!

内容审核压力

2026 年，同公司的 LiblibAI 平台被央视曝光：有用户用复杂提示词绕过审核，生成了违规视频。

常见问题

Q1为什么用画布，不用剪辑软件那种时间轴？
参考答案
  • AI 生产是一张依赖图：剧本 → 分镜 → 角色 → 镜头，每一步都依赖上一步的产物，节点图能直接画出这种关系
  • 好改：改一个节点只影响下游，不用整片重来
  • 能复用：整条流程存成模板，换个剧本再跑一遍
  • 代价：最终的节奏和剪辑还是时间轴擅长，所以成片阶段要导出
Q2「人和 Agent 共用一条管线」有什么好处？
参考答案
  • 能接力：Agent 先批量出初稿，人打开同一块画布精修，不用来回导入导出
  • 多一个入口：用户在自己的 Agent 里也能用 LibTV，平台不只靠自家网页拉用户
  • 一套计费和权限：两种入口走同样的账号和额度
Q3不做模型的视频应用，壁垒在哪？
参考答案
  • 工作流：客户缺的不是单镜头生成，而是从剧本到成片的完整生产能力
  • 时机：比别人早一步判断模型下一代会解决什么问题，提前做好产品形态
  • 用户和内容沉淀：模型社区、素材、模板、团队客户
  • 风险：模型厂商自己做工作流，或者降价，护城河会被重新估值

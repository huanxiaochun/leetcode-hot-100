# 异步协作：人只在关键节点出现

plan = session.plan()           # 人确认或修改计划

    session.step()              # shell / 编辑器 / 浏览器

关键组件

🖥

云端 VM

每个会话一台独立机器，可以预装依赖、保存成快照，下次直接复用。

🧰

三件套工具

Shell 跑命令，编辑器改代码，浏览器查文档、测网页。

🗺

规划器

开工前先出计划，执行中边做边更新，人能看到它打算干什么。

🧠

Knowledge

团队沉淀的知识条目，按触发条件自动召回，Devin 也会建议新增。

📘

Playbooks

可复用的任务模板：步骤、要求、注意事项，同类任务反复用。

💬

协作入口

Slack、Linear、GitHub 里派活和沟通，做完通知你。

知识与上下文

让它像老员工一样懂这个仓库

  • 代码库索引：对接入的仓库预先建索引，生成 Wiki 式文档（DeepWiki）
  • Devin Search：基于索引问答，回答附代码出处
  • Knowledge：长期记忆，跨会话生效，不用每次重新交代
  • Playbooks：把「怎么做」写死，减少每次重新探索
  • VM 快照：环境状态也是上下文，装好的依赖不用重来

常见问题

Q1全异步 Agent 和 IDE 里同步协作的 Agent，各有什么取舍？
参考答案
  • 异步：人省时间、可并行，但走偏了发现得晚
  • 同步：随时纠偏、反馈快，但人要一直盯着
  • 折中：开工前确认计划，卡住时主动求助
Q2为什么给 Agent 一整台 VM，而不是只给 shell？
参考答案
  • 能力：浏览器能查资料、测 UI，完成端到端任务
  • 隔离：在自己的机器上随便折腾，不碰用户电脑
  • 复用：环境做成快照，下次秒起
  • 代价：成本高、启动慢，需要按用量计费
Q3Knowledge 和 Playbooks 有什么区别？
参考答案
  • Knowledge：事实型记忆，「我们用 pnpm」，按场景自动召回
  • Playbooks：流程型模板，「升级依赖分这几步」，派任务时指定
  • 共同点：都是把人的经验外化，减少重复交代

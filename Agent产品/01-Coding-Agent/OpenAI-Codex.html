关键组件

⌨

Codex CLI

开源，用 Rust 写，在本机终端跑，支持交互和 exec 无头模式。

☁

云端任务

每个任务一个隔离容器，后台跑完再看结果，可并行多个。

🔒

沙箱

macOS 用 Seatbelt，Linux 用 Landlock + seccomp，限制写入路径和网络。

📄

AGENTS.md

仓库里的说明文件：怎么装依赖、怎么跑测试、代码规范。按目录层级叠加。

✅

审批策略

从「每步都问」到「从不问」多档可选，和沙箱权限组合使用。

🧩

扩展点

支持 MCP；GitHub 里可以 @codex 做代码审查或接任务。

上下文与环境

上下文靠探索，环境靠配置

  • 不建索引：和 Claude Code 一样，用 shell 命令（rg、cat）现查现读
  • AGENTS.md：根目录到当前目录逐层合并，越深越优先
  • 环境脚本：云端容器先跑安装脚本，Agent 才能真的跑测试
  • 默认断网：云端 Agent 阶段默认不能联网，可按域名放开
  • 会话压缩：长对话可以压缩成摘要继续

设计亮点

🧱

沙箱优先

用 OS 级隔离代替逐条确认，放手让它跑，也跑不出边界。

🔀

本地 + 云端

小改动本地结对，大任务丢云端，同一个账号和模型。

⏩

并行 + 多方案

多个任务同时跑，同一任务也能生成多个版本挑最好的。

📜

可验证的交付

结果附上终端日志和测试输出，审查者能看到它做了什么。

常见问题

Q1沙箱和审批为什么要拆成两个设置？
参考答案
  • 沙箱：技术上能做什么，由操作系统强制
  • 审批：什么时候停下来问人，是交互策略
  • 组合：沙箱兜底后可以少问，体验和安全不用二选一
Q2云端并行任务要解决哪些工程问题？
参考答案
  • 环境复现：安装脚本 + 缓存，容器起得快、能跑测试
  • 隔离：每任务一个容器，互不污染
  • 安全：默认断网，防止提示注入把代码外传
  • 交付：diff + 日志，人审查后再合并
Q3AGENTS.md 解决什么问题？
参考答案
  • 项目知识：测试命令、规范这些模型猜不到的东西写下来
  • 通用格式：多家 Agent 工具都认，不用每家一个文件
  • 分层：子目录可以覆盖父目录的约定

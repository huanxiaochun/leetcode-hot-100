# 一次检索增强问答
queries = rewrite(question, history)       # 结合追问的上下文
docs    = search(queries)                  # 网页、新闻、论文……
chunks  = rerank(extract(docs), question)  # 段落级打分
answer  = llm("只根据以下资料回答，并标注编号", chunks, question)
show(answer, sources=chunks)               # 来源卡片放在答案上方

检索与引用

引用是产品的核心，不是附加功能

  • 先检索再生成：模型只看检索到的段落，不靠记忆回答
  • 句级标注：每句后标编号，点开就是原文
  • 来源在前：答案上方先列来源卡片，用户先看到出处
  • 追问：后续问题带着对话上下文重新检索
  • 聚焦范围：可以限定只搜学术、社交、财经等来源
标了引用也可能错：来源本身不准，或模型误读原文。还有出版方对抓取内容的版权争议。

常见问题

Q1设计一个答案引擎，链路怎么搭？
参考答案
  • 查询改写：结合对话历史，拆成多个搜索词
  • 召回：搜索 API / 自建索引，取前若干网页
  • 抽取 + 重排：切段落，用重排模型打分
  • 生成：约束只用给定资料，强制标引用
  • 后处理：检查引用编号是否真的支撑这句话
Q2怎么保证引用是真的，而不是模型编的？
参考答案
  • 编号来自检索结果：模型只能引用给它的编号，不能自造链接
  • 事后校验：用小模型判断句子和原文是否一致
  • 资料不够就说不知道：在提示里明确要求
Q3Perplexity 和 Deep Research 的区别？
参考答案
  • 深度：Perplexity 默认一两轮检索，Deep Research 几十轮
  • 延迟：秒级对分钟级
  • 场景：查事实、快问答 vs 写调研报告
  • 趋势：两边在靠拢，Perplexity 也有研究模式

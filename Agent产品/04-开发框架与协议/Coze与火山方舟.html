Coze 与火山方舟

产品定位

字节的两层 Agent 基建：扣子让人拖拽搭 Agent，方舟给开发者模型和 API
公司
字节跳动 / 火山引擎
扣子 Coze
低代码 Agent 平台，2025-07 开源 Coze Studio
火山方舟
大模型服务平台：推理、精调、评测
模型
豆包 Seed 系列为主，也有 DeepSeek 等三方模型
一句话记住：扣子面向“搭应用”，方舟面向“调模型”。扣子里的大模型节点，底层就是方舟上的模型。

核心工作原理

STEP 1
人设与回复逻辑
写 Bot 的系统提示，选模型
→
STEP 2
挂技能
插件、工作流、知识库、数据库、变量
→
STEP 3
调试
预览对话，看每步调用了什么
→
STEP 4
发布
飞书、抖音等渠道，或 API / SDK
↻ 对话时模型按人设决定调哪个插件或工作流，结果回填后继续回答，和 Function Calling 同一个循环

关键组件

🤖

Bot / 智能体

人设 + 模型 + 技能。单 Agent 模式，也有多 Agent 模式按节点跳转。

🔀

工作流

画布拖节点：大模型、插件、代码、知识库、条件、循环。固定流程不靠模型猜。

🔌

插件

把 HTTP API 包成工具，填好参数说明，模型就能调。有官方插件商店。

📚

知识库

上传文档、表格、网页，自动切片向量化，对话时检索召回，就是托管版 RAG。

⚡

方舟 · 模型服务

在线推理、批量推理、上下文缓存、模型精调、评测。按 token 计费。

🛠

方舟 · Agent 能力

Responses API 管上下文和工具调用；应用实验室支持零代码和高代码搭应用；可接 MCP 服务。

火山引擎还有 AgentKit（Agent 运行时、沙箱工具等）和开源的 VeADK 开发套件，偏向代码开发的 Agent 上云部署。

记忆与上下文

扣子这边

  • 对话历史：可设带入的轮数，控制长度
  • 变量：存用户昵称、偏好这类键值，跨会话保留
  • 数据库：结构化存记录，比如记账、待办，Bot 可用自然语言读写
  • 长期记忆：自动总结对话里的用户信息，下次召回

方舟这边

  • 上下文缓存：重复的长前缀缓存下来，降成本和首 token 延迟
  • Responses API：服务端存上下文，下一轮传上一次的 id 即可，不用重发全量
  • 无状态 Chat API：兼容 OpenAI，历史由调用方自己管

常见问题

Q1Bot 里什么时候用插件，什么时候用工作流？
参考答案
  • 插件：单个原子能力，查天气、搜索，交给模型自己决定调不调
  • 工作流：多步骤、顺序固定、要稳定输出，如审批、报表生成
  • 组合：工作流里也能调插件，Bot 把工作流当成一个大工具
Q2知识库召回不准，你会怎么调？
参考答案
  • 切片：按标题层级分段，别把一个知识点切断
  • 检索：语义 + 全文混合检索，加 rerank
  • 参数：调召回条数和相似度阈值
  • 查询改写：结合多轮上下文把用户问题改写完整再检索
Q3如果让你在方舟上从零做一个 Agent 服务，链路怎么设计？
参考答案
  • 模型层：按任务选模型，复杂推理用强模型，路由和分类用小模型
  • 编排层：自写循环或用 LangGraph / VeADK，工具走 Function Calling 或 MCP
  • 成本：固定的系统提示走上下文缓存，离线任务走批量推理
  • 质量：上线前用评测集回归，线上看 trace 定位坏例
Q4低代码平台和代码框架各自的天花板在哪？
参考答案
  • 低代码：上手快、迭代快；复杂状态、精细控制、版本管理和测试难做
  • 代码框架：完全可控、好测试；开发和运维成本高
  • 常见做法：原型在扣子验证，量大、逻辑复杂后迁到代码框架

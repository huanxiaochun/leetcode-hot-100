LangGraph

产品定位

把 Agent 写成一张有状态的图：节点干活，边决定下一步，状态随时存档、随时恢复
公司
LangChain
发布
2024-01 开源，2025-10 发布 1.0
形态
Python / JS 库，开源（MIT）
模型
不绑定，任意 LLM
一句话记住：低层编排框架，不替你写 prompt，只管流程控制、状态持久化、人工介入。

核心工作原理

STATE
定义状态
TypedDict，每个字段可配 reducer
→
NODE
节点
普通函数：读状态，返回要更新的字段
→
EDGE
边
固定边，或按状态走条件边
→
COMPILE
编译运行
挂上 checkpointer，invoke / stream
↻ 条件边可以指回前面的节点，所以图里能有环，这就是 Agent 循环
# 最小 ReAct：llm 节点 ⇄ tools 节点
class State(TypedDict):
    messages: Annotated[list, add_messages]   # reducer：追加而不是覆盖

g = StateGraph(State)
g.add_node("llm", call_model)
g.add_node("tools", ToolNode(tools))
g.add_edge(START, "llm")
g.add_conditional_edges("llm", tools_condition)  # 有工具调用 → tools，否则 → END
g.add_edge("tools", "llm")
app = g.compile(checkpointer=InMemorySaver())
app.invoke(inp, {"configurable": {"thread_id": "u1"}})

关键组件

🗂

State + Reducer

状态是共享的字典。reducer 决定多个节点写同一字段时怎么合并。

🔀

条件边

一个路由函数看状态，返回下一个节点名。分支、循环都靠它。

📨

Send / Command

Send 动态扇出做 map-reduce；Command 在节点里同时更新状态并跳转。

💾

Checkpointer

每一步后存一份快照，按 thread_id 区分会话。内存、SQLite、Postgres 都有现成实现。

✋

interrupt()

节点里暂停，把值抛给人；人审批后用 Command(resume=...) 继续。

🧩

子图

一张编译好的图可以当另一张图的节点，多 Agent 就是图套图。

状态与持久化

两种记忆，分开存

  • 短期记忆：checkpointer 按 thread 存每步状态，同一会话多轮对话自动接上
  • 长期记忆：Store 按 namespace 存键值，可跨 thread 共享，比如用户偏好
  • 持久执行：进程挂了，从最后一个 checkpoint 接着跑，不用从头来
  • 时间旅行：取历史 checkpoint，改状态后从那一步重放，方便调试
  • 流式输出：可按状态更新、完整状态、LLM token 等模式流式返回
坑：resume 时被中断的节点会从头重跑，interrupt() 之前的副作用要做成幂等。

设计亮点

🎛

可控性优先

流程由开发者画死，LLM 只在节点里做局部决策，生产环境更可预测。

⏸

人在回路是一等公民

暂停、审批、改状态、恢复，都建立在 checkpoint 之上，不用自己造轮子。

🧱

低层不黑盒

不藏 prompt、不强加架构。create_react_agent 这类预制件只是可选封装。

🔭

配套生态

LangSmith 做追踪和评测，官方部署服务托管长任务，Studio 可视化调图。

常见问题

Q1LangGraph 和 LangChain 什么关系？为什么要单独做？
参考答案
  • LangChain：组件库（模型、工具、检索），早期 Chain 是线性 DAG
  • 问题：Agent 需要循环、分支、暂停，线性链表达不了
  • LangGraph：补上运行时，支持环、状态、持久化、人工介入
  • 现在：LangChain 1.0 的 Agent 就跑在 LangGraph 上
Q2Checkpointer 解决了什么问题？
参考答案
  • 多轮对话：同一 thread_id 自动续上历史状态
  • 容错：崩溃后从最近一步恢复
  • 人工介入：暂停时状态落库，人可以隔几小时再来审批
  • 调试：回到任意一步重放
Q3多个节点并行写同一个字段会怎样？
参考答案
  • 没 reducer：同一步多个写入会报错
  • 有 reducer：按函数合并，如 operator.add 拼列表、add_messages 按 id 去重追加
  • 执行模型：按 super-step 推进，同一步的节点并行，步结束统一合并状态
Q4什么时候选 LangGraph，什么时候不选？
参考答案
  • 选：流程复杂、要审批、要长时间运行、要可恢复
  • 不选：简单的单 Agent + 工具，直接写循环或用轻量 SDK 更快
  • 权衡：控制力换来的是更多样板代码和学习成本

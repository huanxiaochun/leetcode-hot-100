416. 分割等和子集

中等 动态规划 LeetCode ↗

转化：能不能挑出几个数，和正好是总和的一半。状态：dp[j] = 用已经看过的数，能不能凑出和 j。每个数只能用一次（0/1 背包），所以 j 要从大到小更新。

每加入一个数后的 dp（✓ = 能凑出这个和）。下标 j 是「和」
正在更新的这一行：j 从大到小　蓝 dp[j]　橙 dp[j − x]

  

  

  



  

    
解题五步

    
所有动态规划题都按这五步想：先把「状态」说清楚，剩下几步就顺了

    
1状态定义
dp[j] = 用已经看过的这些数（每个最多用一次），能不能挑出几个、和正好是 j
2转移方程
dp[j] = dp[j] || dp[j − x]对新来的数 x：不用它，原来能凑出 j 的还能；用它，原来能凑出 j − x 的，加上 x 就是 j
每个数「用 / 不用」
3初始化
dp[0] = true，其余 false；总和是奇数直接返回 false一个都不挑，和就是 0；问题变成能不能凑出 target = sum / 2
4遍历顺序
外层枚举数，内层 j 从 target 倒着走到 xdp[j − x] 在 j 左边，倒着走时它还是「加入 x 之前」的值，x 就只会被用一次
如果正着走（只有一个 3）：dp[3] 刚变 ✓，dp[6] 接着用它，3 被用了两次 ✗
5答案
dp[target]

  

  

    
为什么不能直接暴力递归

    
把递推式直接写成递归：同一个子问题会被算很多遍。同色的格子就是重复算的

    
nums = [1, 1, 2, 2]，target = 3。结点「i, j」表示：从第 i 个数开始挑，还要凑 j。往下两条边是不选 / 选这个数。两个 1 选哪一个结果都一样，所以同一个「i, j」出现了好几次。
4,1 算了 3 次3,1 算了 2 次2,2 算了 2 次3,2 算了 2 次4,2 算了 2 次
这棵树有 22 个结点，但不同的子问题只有 14 个。动态规划把每个子问题的答案记下来，每个只算一次：
每个和 j 每轮只看一次

  

  

    
归纳 · 同类题 · 易错点

    
0/1 背包可行性：每个物品用或不用，能不能正好装满

    
322 / 279零钱兑换 / 完全平方数
完全背包：每样能用无限次，所以金额从小到大（正着）走；这里每个数只能用一次，倒着走
198打家劫舍
同样是每个元素「选 / 不选」，但约束是「不能相邻」而不是「和等于 target」

    
内层为什么倒序一维 dp[j] 是二维 dp[i][j] 压出来的，dp[j − x] 必须读「上一行」。正着走会读到这一行刚改的值，等于同一个数用了多次（见上面的图）
先判奇数、再判 target总和是奇数不可能平分；某个数比 target 还大也不可能。dp 开 target + 1 个就够，不用开 sum

  
  

    

      
时间O(n × target)

      

        
n 个数×每个更新 target 个和

        
每个数「用 / 不用」两种选择，2ⁿ 种组合；但能凑出的和最多只有 target + 1 种，dp 按和来记，把指数降成了 n × target。

      

      
✓✓✗✗✗✓✓
加入 5 后：0、1、5、6 都能凑出

    

    

      
空间O(target)

      

        
一行 target + 1 个布尔值

        
二维写法 dp[i][j]（前 i 个数能否凑出 j）只依赖上一行，压成一行时必须倒着更新，才能保证读到的是上一行的值。

      

    

    

      
对比暴力 O(2ⁿ)

      

        
枚举每个数选不选是 2ⁿ。不同的选法常常凑出同一个和（1+5 和 6 都是 6），dp 只关心「和能不能凑出」，重复的选法自动合并了。

208. 实现 Trie (前缀树)

中等 图论 LeetCode ↗

每个结点有 26 个孩子（a ~ z）。单词就是从根往下的一条路，公共前缀共用同一段路。走完单词的那个结点打上 isEnd 标记。search 要走得通而且 isEnd；startsWith 只要走得通。

解题要点

    

      
结构每个结点有 child[26] 和 isEnd。字母放在边上（这里画在子结点里），根不代表任何字母。
走路insert、search、startsWith 都是从根出发，按 c − 'a' 往下走。insert 没路就新建，查询没路就返回。
标记isEnd 只在 insert 走完整个单词时打上，它区分「是一个完整单词」和「只是某个单词的前缀」。
答案search = 走得通 且 isEnd；startsWith = 走得通就行。两个函数唯一的区别就在最后这一步。

      
只 insert 了 "apple" 时，"app" 三个字母都走得通，停在橙色结点。它的 isEnd 是 false：是前缀，不是单词。再 insert("app") 才会把它标成 isEnd。

    

  

  

    
归纳 / 同类题提醒

    

      
前缀树 (Trie)一堆字符串里查「有没有这个词」「有没有这个前缀」。

      
和哈希集合比：set 查整词快，但查前缀要把每个词都比一遍；Trie 查前缀和查整词一样快，都是 O(L)。
同类题：212. 单词搜索 II（网格 DFS + Trie 剪枝）、211. 添加与搜索单词（遇到 . 时 DFS 所有孩子）、自动补全。

      
易错：search 忘了看 isEnd只判断走不走得通，"app" 在只插入过 "apple" 时会错误地返回 true。
易错：C++ 内存用裸指针 new Node 要自己写析构递归 delete；用 unique_ptr 或者数组池就不用操心。

    

  

  

    

      
时间O(L)

      

        
每次操作只沿着单词往下走 L 步→每步 child[c − 'a'] 是 O(1)

        
L 是这次单词的长度，和已经存了多少个单词无关。这就是字典树的好处：查一个前缀，不需要把每个单词都比一遍。

      

      
a→p→pl→e
"app" 和 "apple" 共用前三个结点

    

    

      
空间O(N·26)

      

        
最多 N 个结点×每个结点 26 个指针

        
N 是所有插入单词的总字母数（共用前缀的部分只算一次）。search 和 startsWith 的区别只在最后一步：search 还要看 isEnd，startsWith 不看。

      

    

    

      
对比哈希集合存单词

      

        
用 set 存所有单词：search 平均 O(L)，但 startsWith 要把每个单词都检查一遍，O(单词数 × L)。如果把所有前缀也塞进 set，空间会变成所有前缀的总长度。

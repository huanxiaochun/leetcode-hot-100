207. 课程表

中等 图论 LeetCode ↗

[a, b] 画成箭头 b → a。入度 = 还差几门先修课。入度为 0 的课现在就能修，修完把它指出去的箭头都划掉，对方入度 −1，减到 0 就也能修了（拓扑排序）。最后看能不能修完全部。

课程依赖图（箭头 b → a：先修 b 才能修 a；角上的数字是入度）
在队列里正在修修完了环上的课

  

  

  


  

    
解题要点

    

      
图把 [a, b] 存成邻接表 next[b] = {a, …}，同时数 indeg[a]：还差几门先修课。
BFSKahn 算法：入度为 0 的进队列；取出一门 = 修完它，把它指向的课入度 −1，减到 0 才进队。
标记不需要 visited：一门课只在入度变成 0 的那一刻进一次队，之后不会再变成 0。
答案数出队了几门 done。done == numCourses 就能修完，否则剩下的课里一定有环。

      
左边 3 号课有两门先修，修完 1、2 后入度 2 → 1 → 0 才能修。右边 1 → 2 → 3 → 1 绕成一圈，每门的入度都卡在 1，谁也进不了队列。

    

  

  

    
归纳 / 同类题提醒

    

      
拓扑排序有先后依赖关系，问能不能排出一个顺序。

      
拓扑排序能顺便判环：出队数量 < 结点数，就说明有环。210. 课程表 II 只是把出队顺序记下来返回。
和 200 / 994 对照：网格题的边是隐式的上下左右；这题的边要自己从 prerequisites 建，而且是有方向的。

      
易错：边的方向[a, b] 是「先修 b 才能修 a」，边是 b → a，入度加在 a 上。方向反了结果可能还对，但修课顺序是反的。
易错：判环不能只看有没有入度 0有入度 0 的课不代表没环，比如例 2：0 和 4 能修，1、2、3 绕成环。一定要数 done。

    

  

  

    

      
时间O(V + E)

      

        
每门课进队、出队各 1 次+每条箭头被划掉 1 次

        
V 是课程数，E 是先修关系数。有环就修不完：环上每门课都至少有一个箭头来自环上的另一门，它们谁都没法先变成 0，所以 done 一定小于 V。

      

      
1→2→3→1
环上每门入度至少是 1，永远进不了队列

    

    

      
空间O(V + E)

      

        
邻接表存 E 条边+入度数组和队列 O(V)

        
题目给的是「边的列表」，先转成邻接表 next[b] = {a, …}，这样修完 b 时能直接找到它的后续课。

      

    

    

      
对比DFS 三色 O(V + E)

      

        
也可以 DFS 判环：每门课三种状态，白没访问、灰在当前递归路径上、黑已经确认没问题。DFS 时碰到灰色，说明绕回了自己的路径，就是环。
